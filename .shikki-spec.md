# CoreKit device-capacity prober (W1)

## Phase 1 — Why

The parent spec (4b8e21c9 rev 5) needs one honest, cross-platform
measurement of what a device can actually spend on a model. Today the
only such measurement is `SystemMetricsProvider`
(`Sources/ShiKit/ShiKitResourceGovernor/SystemMetricsProvider.swift:24`
in the shikki repo): percentage-shaped, device-wide, and locked inside
the shikki app target, so neither AIKit nor shikki-client can reach it
and it cannot express a phone's per-process reality.

Per BR-CF-07 the measurement belongs in **CoreKit** — a memory probe
carries no AI concepts — and the protocol ships together with its
implementations so nothing has to conform across a package boundary.
AIKit will later depend on CoreKit for the snapshot VALUE (W1b); CoreKit
gains no new dependency here.

Founding fixture, same day: a 64 GB M2 Max carrying 40 GB of swap. Total
RAM alone said "plenty"; the live state said otherwise. Both numbers must
survive into the snapshot.

## Phase 2 — Business Rules

- **BR-CP-01 (measured, never inferred)** — every field comes from a
  device API at call time. No cached hardware assumptions, no values
  derived from model-card prose or marketing names. This is the 36-GB
  lesson from the parent spec and it is the reason this wave exists.

- **BR-CP-02 (basis is explicit and typed)** — macOS and iOS do not mean
  the same thing by "available memory". The snapshot carries
  `basis: CapacityBasis` (`.deviceWide` | `.perProcess`) so a consumer can
  never read a per-process number against a device-wide budget. On macOS
  the numbers are device-wide (`hw.memsize` + host statistics). On iOS the
  binding constraint is the per-process jetsam limit, so
  `ProcessInfo.physicalMemory` is NOT a spendable budget and must never be
  reported as `availableNow`.

- **BR-CP-03 (live pressure is first-class)** — `totalRAM` alone is not a
  verdict input. `availableNow`, `swapInUse` and `thermalState` are
  carried alongside it, because the same machine gives a different honest
  answer idle vs under pressure.

- **BR-CP-04 (one seam, injectable)** — all reads go through
  `DeviceCapacityProbing`. No call site reads `sysctl`, `host_statistics64`
  or `os_proc_available_memory` directly outside the platform prober.
  `MockCapacityProber` is the test seam; tests never touch real hardware
  state.

- **BR-CP-05 (sandbox-legal only)** — iOS uses only APIs legal inside the
  app sandbox (`os_proc_available_memory`, `ProcessInfo.thermalState`).
  No `vm_stat` subprocess, no private API. If a field cannot be measured
  legally on a platform, it is `nil` and documented as such — never
  faked with a plausible constant.

- **BR-CP-06 (failure is nil, not a lie)** — a probe that cannot read a
  value reports `nil` and logs. It never substitutes a default that would
  read downstream as a measurement.

## Phase 3 — Implementation Waves

### Wave 1: DeviceCapacitySnapshot + probing seam ← NO DEPENDENCY

**Files:** `Sources/CoreKit/Capacity/DeviceCapacitySnapshot.swift` (new —
`totalRAM`, `availableNow`, `swapInUse`, `thermalState`, `chipClass`,
`gpuWorkingSetLimit`, `basis: CapacityBasis`; `Sendable`, `Equatable`,
`Codable` per [[json-means-codable-typed-model]]),
`Sources/CoreKit/Capacity/DeviceCapacityProbing.swift` (new — the
protocol, `Sendable`),
`Sources/CoreKit/Capacity/PlatformCapacityProber.swift` (new — macOS
`hw.memsize` + `host_statistics64` + Metal `recommendedMaxWorkingSetSize`
where available; iOS `os_proc_available_memory` + jetsam limit + thermal;
`#if os(...)` split inside the one type),
`Sources/CoreKit/Capacity/MockCapacityProber.swift` (new — injectable
fixture prober),
`Tests/CoreKitTests/Capacity/DeviceCapacitySnapshotTests.swift` (new),
`Tests/CoreKitTests/Capacity/PlatformCapacityProberTests.swift` (new),
`.kagami/scopes.override.toml` (new `CoreKitCapacity` scope entry
following the existing `CoreKitCache`/`CoreKitDrain`/`CoreKitHash`
convention — a new scope MUST be registered in the same change that
creates its tests).

**Tests:**

- `T-CP-01_snapshotRoundTrips` — snapshot encodes/decodes losslessly.
- `T-CP-02_mockProberDrivesFields` — every field originates from the
  injected prober; no ambient reads leak in.
- `T-CP-03_livePressureChangesAvailableNow` — two fixture probes with
  different pressure yield different `availableNow`, same `totalRAM`.
- `T-CP-04_basisIsPlatformCorrect` — macOS build reports `.deviceWide`,
  iOS build reports `.perProcess`.
- `T-CP-05_unmeasurableFieldIsNil` — a prober that cannot read a field
  yields `nil`, never a substituted constant (BR-CP-06).
- `T-CP-06_noDirectSyscallOutsideProber` — ratchet: grep the CoreKit
  sources for `sysctl`, `host_statistics`, `os_proc_available_memory`
  and assert the only hits are inside `PlatformCapacityProber.swift`.
- `T-CP-07_realProbeIsSane` — the live macOS prober returns
  `totalRAM > 0` and `availableNow <= totalRAM`. This is the only test
  touching real hardware, and it asserts invariants rather than values so
  it is not machine-specific.

**Gate:** `kagami test --scope CoreKitCapacity --strict`

## Phase 4 — Test plan

| id        | asserts                                            |
| --------- | -------------------------------------------------- |
| `T-CP-01` | snapshot Codable round-trip                        |
| `T-CP-02` | all fields sourced from the injected prober        |
| `T-CP-03` | live pressure moves `availableNow`, not `totalRAM` |
| `T-CP-04` | `CapacityBasis` matches the compiled platform      |
| `T-CP-05` | unmeasurable field is `nil`, never a fake default  |
| `T-CP-06` | ratchet — syscalls confined to the prober          |
| `T-CP-07` | live macOS probe satisfies its invariants          |

When a snapshot is encoded and decoded:

- every field survives unchanged, including `nil` fields and `basis`
  (`T-CP-01`).

When a consumer builds a snapshot from an injected `MockCapacityProber`:

- every populated field traces to a prober value, and no ambient device
  read contributes (`T-CP-02`).

When two fixture probes differ only in memory pressure:

- `availableNow` differs and `totalRAM` does not (`T-CP-03`).

When the prober runs on macOS:

- `basis` is `.deviceWide` (`T-CP-04`).

When the prober runs on iOS:

- `basis` is `.perProcess`, and `ProcessInfo.physicalMemory` is never
  reported as `availableNow` (`T-CP-04`, BR-CP-02).

When a platform cannot legally measure a field:

- the field is `nil` and a diagnostic is logged; no constant is
  substituted (`T-CP-05`, BR-CP-06).

When the CoreKit sources are scanned for raw capacity syscalls:

- the only occurrences of `sysctl`, `host_statistics` and
  `os_proc_available_memory` are inside `PlatformCapacityProber.swift`
  (`T-CP-06`, BR-CP-04).

When the live macOS prober is invoked:

- `totalRAM > 0` and `availableNow <= totalRAM` (`T-CP-07`).

## Silent-fail enumeration

A measurement primitive fails dangerously when it returns a number that
LOOKS measured but is not. Each row is a way that could happen here.

| Class               | What                                                                                                                                                                              | Detection                                             | Test-name                                 |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- | ----------------------------------------- |
| substituted-default | a probe fails and a plausible constant (e.g. 8 GB) is returned instead of `nil`, so every downstream verdict is confidently wrong                                                 | field is non-nil while the underlying syscall errored | `T-CP-05_unmeasurableFieldIsNil`          |
| basis-confusion     | an iOS per-process `availableNow` is read against a device-wide budget (or the reverse), silently over-committing memory by an order of magnitude                                 | `basis` does not match the compiled platform          | `T-CP-04_basisIsPlatformCorrect`          |
| ambient-read-leak   | a call site bypasses the seam and reads `sysctl` directly, so tests pass against fixtures while production reads real hardware — the two paths drift and only production is wrong | syscall symbols appear outside the prober             | `T-CP-06_noDirectSyscallOutsideProber`    |
| stale-total-as-live | `totalRAM` is reported in the `availableNow` slot, so a swap-saturated machine reads as idle — this is exactly the 64 GB / 40 GB-swap fixture that motivated the parent spec      | pressure changes fail to move `availableNow`          | `T-CP-03_livePressureChangesAvailableNow` |
| lossy-transport     | a snapshot crosses a process or storage boundary and a `nil` becomes `0`, converting "unmeasured" into "measured as zero"                                                         | round-trip inequality                                 | `T-CP-01_snapshotRoundTrips`              |
